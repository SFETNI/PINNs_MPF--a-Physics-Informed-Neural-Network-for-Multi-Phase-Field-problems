# PINNs-MPF — Technical Report

This report documents the governing physics, the physics-informed loss formulation, and
the per-benchmark numerical considerations behind the PINNs-MPF validation package. It is
the technical companion to the [README](README.md); read that first for the high-level
method and the visual results.

PINNs-MPF accompanies *Elfetni & Darvishi Kamachali, Engineering Analysis with Boundary
Elements 176 (2025) 106200*. This release is an upgrade of the published implementation:
the physics and the space–time decomposition are unchanged, the code is consolidated and
runs natively on GPU in double precision, and the multiphase output is handled by a single
softmax per worker (see [Multiphase Formulation](#multiphase-formulation-b5)).

## Method Overview

PINNs-MPF approximates the phase-field evolution `φ(x, y, t)` with neural networks and
trains them against the governing PDE rather than against supervised field snapshots. Two
decompositions make large, stiff problems tractable:

- **Spatial decomposition.** The periodic domain `[0, L]²` is split into an `nx × ny` grid
  of overlapping sub-boxes, each carried by its own **worker network** (an MLP). Each worker
  sees a small region where the interface is locally near-flat, avoiding the global
  "grow-to-lower-curvature" residual basin that defeats a single network (quantified in
  [B2](#b2-single-network-limit)). Workers are stitched into one field by an
  **internal-continuity** loss on their overlap halos and a **periodic-seam** loss on the
  domain boundary.
- **Temporal decomposition (time marching).** The trajectory is advanced through successive
  **time windows**. Within a window the workers are trained under the physics-informed loss;
  the converged field is then handed off as the initial condition of the next window.

## Numerical Stack

- Python / TensorFlow, `float64` throughout.
- Adam warm-up followed by L-BFGS polish (TensorFlow Probability); for the stiff driven case
  the two are cycled per interval to a convergence threshold (see [B3](#b3-driven-force-grain-shrinkage)).
- Reference solutions are generated by analytic formulae or explicit finite-difference
  phase-field solvers (`reference/`), never used as in-window training labels.
- Training runs on a single GPU in `float64`; double precision is throughput-limited on
  consumer-class GPUs, so long runs are budgeted accordingly.

## Governing Physics And Losses

### Single-Phase Formulation (B1, B3, B4)

A single order parameter `φ ∈ [0, 1]` evolves under the sinusoidal multi-phase-field
equation, with an optional bulk driving force `Δg`:

```text
∂φ/∂t = μ [ σ ( ∇²φ + π²/(2η²)(2φ − 1) )  +  (π/η) √(φ(1 − φ)) Δg ]
```

- `Δg = 0` gives curvature-driven motion; the sharp-interface radius law is the parabola
  `R²(t) = R₀² − 2μσt` (B4).
- `Δg ≠ 0` adds a constant shrinking term; the law becomes `dR/dt = −μ(σ/R + |Δg|)`, faster
  and closer to linear (B3).

### Multiphase Formulation (B5)

The triple junction evolves `N` phase fields `φ_α(x, y, t)`, `α = 1 … N`, subject to the
phase-sum constraint

```text
Σ_α φ_α = 1 ,      φ_α ∈ (0, 1).
```

Each phase obeys the multi-phase-field equations (paper Eqs. 22–23, equal interfacial
energies `σ`, no driving force):

```text
I_α       = ∇²φ_α + (π²/η²) φ_α
∂φ_α/∂t   = (μ/N) Σ_{β≠α} σ ( I_α − I_β )   =   μ σ ( I_α − (1/N) Σ_β I_β )
```

The pairwise phase interactions `Σ_{β≠α}(I_α − I_β)` collapse to the mean-subtracted form on
the right. That form makes `Σ_α ∂φ_α/∂t = 0`, so the phase-sum constraint is **conserved by
the dynamics**. For `N = 2` the system reduces exactly to the single-phase curvature equation
above — a rigorous cross-check of the multiphase model against the single-phase solver.

In PINNs-MPF each worker outputs `N` logits that a **softmax** maps to `φ_α`, so `φ_α ∈ (0,1)`
and `Σ_α φ_α = 1` hold **by construction** — the explicit sum-constraint loss the per-phase
scheme required becomes unnecessary. This softmax, worker-per-subdomain design is the main
implementation upgrade over the published per-phase network stack, and the PDE residual
trained against is `f_α = ∂φ_α/∂t − μσ(I_α − mean_β I_β)`.

### Physics-Informed Loss

Each time window minimizes:

```text
L = w_pde  L_pde                 (PDE residual, sampled on the interface band)
  + w_ic   L_ic                  (initial condition at the window start)
  + w_dn   L_denoising           (bulk stabilization away from the interface)
  + w_cont L_internal_continuity (worker agreement on overlap halos)
  + w_pbc  L_periodic_seam       (periodic-boundary matching)
```

No finite-difference field, radius law, or reference snapshot is used as a training label
inside any window. `L_ic` is the field at the window start (a handoff, not an endpoint
target); reference endpoints are used only for evaluation and figures.

### Reference Solutions: Analytic Theory And The Explicit Finite-Difference Solver

The single-grain benchmarks (B3, B4) are checked against two independent references. Neither is
used as a training label — the PINNs-MPF loss is the physics residual only.

**Analytic sharp-interface theory.** In the limit of a vanishingly thin interface the grain radius
obeys a closed-form law:

```text
curvature-driven (Δg = 0):  R²(t) = R₀² − 2 μ σ t                (B4)
driven force  (Δg ≠ 0):     dR/dt = −μ ( σ/R + |Δg| )            (B3)
```

These are idealizations: they omit the finite interface-width (`η`) correction, so a diffuse-interface
solution is expected to deviate from them by an `O(η/R)` amount, growing as the grain shrinks.

**Explicit finite-difference phase-field solver** (`reference/pf_solver.py`). The same PDE is
integrated directly on a periodic grid at `dx = 1` cell by forward-Euler time-stepping:

```text
φ^{k+1} = clip( φ^k + Δt · μ[ σ(∇²φ^k + π²/(2η²)(2φ^k − 1)) + (π/η)√(φ^k(1−φ^k)) Δg ] , 0, 1)
```

with a 5-point periodic Laplacian for `∇²φ`, and `φ` clipped to `[0, 1]` each step. The step size is a
driving-force-aware CFL limit `stable_dt = min( diffusion dx²/(4μσ), reaction η²/(μσπ²), drive )`,
where the interface-motion term `drive = (dx/2)/(μ|Δg|)` caps front travel at half a cell per step and
is the binding constraint under a strong driving force (`Δg = 0` recovers the two-term limit). The
radius is read from the `φ = 1` area, `R = √(area/π)`. Because the grid is `dx = 1`, this reference
carries its own `O(dx²)` spatial discretization error.

**Roles.** PINNs-MPF is a mesh-free, continuous representation of the same PDE; the analytic law is the
sharp-interface idealization; the finite-difference solver is the explicit numerical reference. All
three are shown together in the B3 figures, and the radius gap is reported **both** against the analytic
theory and against the finite-difference reference (see [B3](#b3-driven-force-grain-shrinkage)). Being
close to one reference is not a claim of superiority over the other.

## Benchmark Results And Considerations

### B1 Traveling Wave

- **Reference:** closed-form traveling-interface solution.
- **Setup:** single network; analytic moving interface.
- **Result:** MSE `2.675e-7`, MAE `1.545e-4`, relative L2 `6.898e-4`; fitted interface
  velocity `0.499818` vs true `0.5` (`0.04%`).
- **Role:** high-precision analytic baseline for the solver.
- **Location:** `validated_benchmarks/B1_traveling_wave/`.

### B2 Single-Network Limit

- **Not a validated benchmark — a motivating demonstration.** It shows why the spatial
  decomposition is necessary.
- **Setup:** one identical driven-force time window (`Δg = −250`, `dt = 0.002`,
  `R₀ = 25.6` cells, `η = 7`), changing only the number of networks.
- **Result:** a single global network cannot hold the sharp interface — peak `φ` collapses to
  `0.55` (MSE `0.182`); a `2 × 2` four-worker decomposition restores it to peak `φ = 0.95`
  (MSE `0.086`) on the same window.
- **Role:** motivates the multi-network, time-marched design validated in B3/B4/B5.
- **Location:** `validated_benchmarks/B2_single_network_driving_force/`.

### B3 Driven-Force Grain Shrinkage

- **Reference:** explicit finite-difference phase-field solver, exact-aligned to machine
  precision at each interval boundary.
- **Setup:** `128 × 128` (`dx = 1`), `μ = σ = 1`, `η = 7` cells, driving force `Δg = −0.5`,
  circular grain `R₀ = 38` cells (driven regime `|Δg|R₀/σ ≈ 19`). A `3 × 3` grid of nine
  overlapping workers with non-uniform box edges `[0, 20, 108, 128]` keeps the shrinking
  grain inside the central worker; each worker is `[x, y, t] → φ`, six layers of 64.
- **Protocol:** 40 uniform intervals of `dt = 1.15` (`t = 0 → 46`), each initialized from the
  previous PINNs-MPF field. Each interval **cycles Adam + L-BFGS until its physics loss
  converges and keeps the best-converged state** — this per-window convergence gate is what
  holds the driven interface accurate; the loss is reference-free within every interval.
- **Result:** through the validation target (interval 20, `t ≈ 23`) the median radius error
  against the finite-difference reference is `1.26%` (max `2.22%`); the shrinkage rate matches the
  reference to within `4%` (`−0.547` vs `−0.525` cell/time); the interface stays full-amplitude and
  circular.
- **Dual gap (reported both ways).** Over the validated region PINNs-MPF sits `0.59%` (median) from
  the analytic sharp-interface law, while the finite-difference reference sits `0.68%` from the same
  law; the `1.26%` headline is the more conservative PINNs-MPF-vs-finite-difference comparison. Much
  of that headline is the finite-difference reference's own `dx = 1` discretization drift away from
  the theory. This is not a claim that PINNs-MPF is more accurate than the finite-difference solver —
  the sharp-interface law is itself an idealization — but both references are kept, with distinct
  roles. Numbers regenerate into `validated_benchmarks/B3_driven_force/data/dual_gap.json`.
- **Known limit:** a small steady over-shrink (~`0.02` cell/interval) accumulates and crosses
  the fixed `0.75`-cell absolute tolerance floor once the grain is small (from interval 29),
  ending at a `1.025`-cell gap at `t = 46`. This is an accuracy limit near extinction, not a
  loss of stability.
- **Extinction demonstration.** A separate, clearly-caveated demonstration
  (`validated_benchmarks/B3_driven_force/demo_extinction/`) marches the same grain to `R → 0` over
  58 intervals, showing the sub-η diffuse-interface limit openly. It is not part of the validated
  claim; no accuracy is claimed below `R ≈ η`.
- **Location:** `validated_benchmarks/B3_driven_force/`.

### B4 Curvature-Driven Grain Shrinkage

- **Reference:** explicit finite-difference phase-field solver and the analytic parabolic law
  `R²(t) = R₀² − 2μσt`.
- **Setup:** `64 × 64`, `μ = σ = 1`, `η = 7` cells, `Δg = 0`, circular grain `R₀ = 25` cells.
  A `2 × 2` grid (early interval) and a `3 × 3` grid with non-uniform edges `[0, 12, 52, 64]`
  (middle/late) keep the grain away from worker seams; radius-spaced adaptive `dt`.

| Interval | Time | Radius (cells) | Mean rel. err | Max rel. err |
|---|---:|---:|---:|---:|
| Early shrinkage | `0 → 188` | `25 → 16.4` | `0.40%` | `1.51%` |
| Middle shrinkage | `163 → 248` | `17.4 → 12.0` | `0.67%` | `1.29%` |
| Late shrinkage | `248 → 283` | `11.95 → 8.49` | `1.29%` | `2.59%` |

- **Considerations:** overlapping early/middle coverage (`t ≈ 163 → 188`) gives an independent
  cross-check from two decomposition layouts; the late interval starts from a single FD field
  handoff at `t ≈ 248`, after which all ICs are PINNs-MPF-propagated. The growing late error
  reflects the diffuse-interface limit at `R/η ≈ 1.2`.
- **Location:** `validated_benchmarks/B4_grain_shrinkage/`.

### B5 Triple Junction

- **Reference:** `128 × 128` finite-difference multiphase-field trajectory from a
  periodic-safe 90-degree initial condition with six visible junctions.
- **Setup:** four phases; four spatial workers on a `2 × 2` decomposition; worker
  `(64,) × 6` with four softmax phase outputs; `η = 6/64`, `μ = 1e-4`, `σ = 1`,
  `τ_c = 87.890625`; eight windows of `dt = 25` (`t = 0 → 200 = 2.276 τ_c`); `n_f = 4800`;
  Adam 800 steps/window; all loss terms active from the first window; per-window IC supplied
  by the FD reference.
- **Result at window 8:** MSE `3.70e-4`, argmax disagreement `1.36%`, angle-tracking gap
  `0.40°`, six junctions retained in every window, max phase-sum error `3.33e-16`, seam
  mismatch `≤ 0.0214` over all windows.
- **Disclosed limit:** window 1 (`t = 0 → 25`) is the fast 90°→near-120° transient (MSE
  `2.80e-3`, angle gap `13.8°`); windows 2–8 satisfy the field, topology, seam, and
  angle-tracking criteria. The result is a time-window validation (each window physics-informed
  and unsupervised inside the window, IC handed off from the FD reference), not a fully
  autonomous rollout from the global `t = 0` field.
- **Location:** `validated_benchmarks/B5_triple_junction/` (with a `64 × 64` comparison in
  `comparison_64x64/`).

## Interpretation

- **B1** confirms high-precision PINNs-MPF learning on an analytic interface.
- **B2** demonstrates why the method decomposes: one network cannot hold a driven interface.
- **B3 and B4** validate the multi-network, time-marched design on driven and curvature-driven
  single-grain shrinkage, with explicit finite-difference comparison and disclosed
  small-radius / near-extinction limits.
- **B5** validates triple-junction topology and field tracking through `t = 200` under the
  time-marched softmax MultiNN protocol, with the first fast transient disclosed.

## Caveats

- B5 is a four-output worker-per-subdomain softmax implementation, not a literal 16
  phase-specific network stack; the phase-sum constraint is enforced by softmax.
- B5 is not a fully autonomous rollout after the global `t = 0`; later window ICs use FD
  handoff.
- B2 is a motivating demonstration, not a validated result; the validated driven-force case
  is B3.
- The pyramidal-training study (**B6**) from the original article remains outside this
  validation package until it is reviewed on its own.

## Reproduce

Lightweight local checks:

```bash
pytest tests/test_b1_regression.py
pytest tests/test_pf_solver.py tests/test_pf_solver_multiphase.py
pytest tests/test_b5_smoke.py
```

Per-benchmark figures regenerate on CPU from the packaged metrics and snapshots (no training,
no reference generation) via each benchmark's `make_*.py`. The validated driven-force run (B3)
is reproducible from the runner's default option `B3_DRIVEN_FORCE`
(`python benchmarks/b3_driven_force/run.py --outdir <dir>`, or `--print-config` to inspect the
exact configuration without training). GPU runs should be launched only after review of the
intended configuration, reference data, expected wall time, and output location.
